# AI CRM 线索评分助手

> 基于 Coze/Dify 搭建的 AI 营销 Agent：RAG 知识库 + 多步骤工作流编排 + 可交互网页 Demo，用于售前需求验证。
> **在线 Demo**：https://ai-crm-lead-scoring.app.workbuddy.host/

## 项目能做什么

输入一条客户线索（行业 / 规模 / 岗位 / 行为 / 留言），AI 自动完成：

1. **透明评分**：属性分(45) + 行为分(25) + 意图分(30)，每项得分可追溯；
2. **自动分级**：≥60 SQL（销售立即跟进）· ≥30 MQL（培育池）· <30 无效（自动过滤）；
3. **生成话术**：基于 RAG 知识库生成个性化跟进消息，答案有出处、不瞎编。

## 快速开始

### 1. 在线体验（0 分钟）
打开 Demo 链接，点击 3 条预置线索（SQL / MQL / 无效）查看完整评分过程与自动动作。

### 2. Dify 一键导入（5 分钟）
```
Dify → 创建应用 → 导入 DSL → 选择 Dify导入_AI-CRM线索评分助手.yml
→ 4 个 LLM 节点绑定模型 → 知识检索节点绑定知识库 → 发布
```

### 3. Coze 手动搭建（2 小时）
按 `Coze搭建包_AI-CRM线索助手.md` 逐步搭建：含每个节点的提示词、代码、测试用例与调试清单。

### 4. 跑通自动化脚本（2 分钟）
```bash
python 批量跟进消息生成.py 示例客户数据.xlsx 跟进消息输出.xlsx
# 读取客户表 → 按意向等级生成个性化消息 → 写回 Excel 新列
```

### 5. 复现数据分析（1 分钟）
```bash
python 商机数据生成与统计.py
# 生成 300 条模拟商机 → 输出商机数据集_模拟300条.xlsx + 统计结果
```

## 核心设计

| 设计点 | 方案 |
|---|---|
| 评分可解释 | 三段式评分，每个节点输出中间分，销售可申诉 |
| RAG 防幻觉 | 话术仅依据知识库检索结果生成，未覆盖内容标注"需与产品确认" |
| 成本控制 | 条件分支前置，无效线索省掉知识库检索与话术生成两次调用（结构化提取与意图评分无法省，否则判不出等级） |
| 数据闭环 | 数据分析定位强/弱信号 → 反哺评分权重（岗位↑ 规模↓） |

## 关键发现（数据分析）

- **角色 > 规模**：采购/IT 负责人 SQL 率是普通员工的 3-4 倍；公司规模只推高平均分；
- **强行为信号**：预约演示 / 试用注册 / 浏览价格页在无效组渗透率为 0；下载白皮书为弱信号；
- **意图直通**：留言出现"API/集成对接"平均 73.6 分，接近 SQL 直通线。

## 质量保障：AI 应用怎么证明「它靠谱」

LLM 应用没法像传统软件那样「测一次就放心」——同样的输入两次可能给出不同结果。所以本项目不测「对不对」，而是测「**在不在可接受范围内**」，用三条线卡住效果：

| 维度 | 指标 | 阈值 | 为什么定这条线 |
|---|---|---|---|
| 分级准不准 | 等级判定一致率（AI vs 人工双盲） | ≥ 80% | 销售认不认可，比数学准确率更重要 |
| 关键场景 | TC-01（SQL）/ TC-05（无效）通过率 | 100% | 漏高价值客户 / 放行垃圾线索，代价最大 |
| 稳不稳 | 同一条线索跑 3 次，分数极差 | ≤ ±5 分 | 分数飘忽，销售就不信这套评分 |
| 兜不兜底 | 解析失败走兜底的比例 | ≤ 5% | 兜底多说明提示词约束不够 |
| 快不快 | 单条线索端到端耗时 | ≤ 30 秒 | 对齐客户验收标准 |
| 越不越界 | 属性分 0-45 / 行为分 0-25 / 意图分 0-30 | 不可越界 | 防止封顶与夹紧逻辑失效导致总分爆表 |

**用例分三层，共 20 条**（`qa/` 目录）：

- **正常用例 6 条**：证明「能用」——三类结果（SQL / MQL / 无效）各有覆盖；
- **边界用例 8 条**：证明「分得准」——卡在 60/30 阈值线上的线索、行为分封顶、属性分上下限夹紧；含 2 条同画像对照组（只换一句留言，验证意图分的区分度）；
- **异常用例 6 条**：证明「崩不了」——空留言、无意义留言、超长文本（2000 字）、多意图混杂、中英混杂，以及人为制造的解析兜底场景。

其中 **TC-11 是一条负向用例**：故意传入评分字典里没有的行为词（「预约演示」vs 字典里的「预约产品演示」），用来主动暴露「前端选项与后端字典键不一致 → 静默计 0 分」这类配置风险。这类问题不主动测，上线后永远发现不了。

测试记录表内置判定公式——填入实际分数与等级后**自动判通过/不通过**（等级命中 + 分数落区间 + 关键词命中三重校验），无需人工比对。

### 本轮执行结果（2026-09 · 规则层离线回归）

| 轮次 | 通过率 | 说明 |
|---|---|---|
| R1 基线 | **18/20（90%）** | 暴露 2 处意图档位盲区：学生/课程/调研类留言按字面落入「一般咨询 7-12」档，把无效线索抬到 9 分 |
| R2 修复后复测 | **20/20（100%）** | 在意图评分提示词中补「非决策场景优先降档」规则后复测通过 |

关键结果：关键用例 TC-01（SQL）/ TC-05（无效）100% 通过；同画像对照组 TC-08A 54 分 vs TC-08B 68 分，**意图分带来 14 分区分度**（设计要求 ≥10）；数值边界 0 次越界（行为分封顶 25、属性分夹紧 0/45 均生效）；阈值敏感区 TC-07 实测 57 分，距 60 分线仅 3 分——这正是提示词档位必须锁死的理由。

> 本轮覆盖的是**确定性那一半**（规则评分、阈值分级、意图档位规则），LLM 真实输出的抖动、话术生成质量与端到端耗时仍需接入模型后复测，报告里已明确标注未覆盖项。

详情见 `qa/测试执行报告_2026-09.md`、`qa/测试结果明细_2026-09.json`，可用 `python qa/run_tests.py` 一键复现。

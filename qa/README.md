# 质量保障（QA）— AI-CRM 线索评分助手

> 目录用途：定义这条 AI 工作流「怎样才算做对了」，并提供可复现的验收资产。
> 面向对象：做 POC 验收的客户方、评审方案的技术负责人、接手维护的同事。

---

## 一、为什么 AI 工作流必须写测试

传统软件是「钥匙配锁」——插进去能开就是对的，测一次就够。
LLM 工作流是「老中医开方」——同一个病人今天和明天开的方子可能不一样。

所以测试目标不是「对不对」，而是「**在不在可接受范围内**」。三个现实理由：

1. **上线要有客观门槛**：没有量化标准，「我觉得差不多了」说服不了客户；
2. **改动要有回归网**：调一次提示词，必须能立刻发现有没有把原本正常的场景弄坏；
3. **演示要有保底**：客户现场不能让模型抽风，需要提前知道异常时的兜底表现。

## 二、用例分层策略（共 20 条）

| 层次 | 条数 | 证明什么 | 典型用例 |
|---|---|---|---|
| **正常用例** | 6 | 能用 | 高分线索判 SQL、弱画像弱行为判 MQL、学生线索自动过滤 |
| **边界用例** | 8 | 分得准 | 卡在 60 分阈值线上、行为分封顶 25、属性分上下限夹紧、两组同画像对照 |
| **异常用例** | 6 | 崩不了 | 空留言、无意义留言、2000 字超长文本、多意图混杂、中英混杂、人为制造解析兜底 |

**为什么边界层最多**：bug 都藏在「差一点」的地方。90 分的线索判成 SQL 谁都不会质疑，但刚好 60 分那条会因为模型多给 1 分就跨级——而客户最关心的恰恰是这条线准不准。本轮实测的 TC-07 就是 57 分，离 SQL 线只差 3 分。

两组**对照组**（TC-08A / TC-08B）是本套用例的核心设计：画像字段完全相同，只把留言从「想了解下功能」换成「支持API对接吗」，要求总分差 ≥ 10 分且等级升为 SQL。实测分差 **14 分**（54 → 68），证明意图分是唯一有效区分度来源——如果两组分数接近，说明意图识别形同虚设。

## 三、通过标准（六条线）

| 维度 | 指标 | 阈值 | 为什么定这条线 |
|---|---|---|---|
| 分级准不准 | 等级判定一致率（AI vs 人工双盲） | ≥ 80% | 销售认不认可，比数学准确率更重要 |
| 关键场景 | TC-01（SQL）/ TC-05（无效） | 100% | 漏高价值客户 / 放行垃圾线索，代价最大 |
| 稳不稳 | 同一条跑 3 次，分数极差 | ≤ ±5 分 | 分数飘忽，销售就不信这套评分 |
| 兜不兜底 | 解析失败走兜底比例 | ≤ 5% | 兜底多说明提示词约束不够 |
| 快不快 | 单条端到端耗时 | ≤ 30 秒 | 对齐客户验收标准 |
| 越不越界 | 属性分 0-45 / 行为分 0-25 / 意图分 0-30 | 不可越界 | 防止封顶、夹紧逻辑失效导致总分爆表 |

## 四、怎么跑（复现步骤）

### 1. 准备被测环境（约 5 分钟）

```
Dify → 创建应用 → 导入 DSL（Dify导入_AI-CRM线索评分助手.yml）
     → 4 个 LLM 节点绑定模型（温度建议 0.2，降低抖动）
     → 知识检索节点绑定 3 份知识库文档
     → 发布
```

### 2. 录入实际结果

打开 `测试用例集_AI-CRM线索评分助手.xlsx`：

- 在 **`测试记录表`** 中，只需填 3 列：`实际总分`、`实际等级`、`关键词命中`；
- `预期值` 由 VLOOKUP 自动从 `测试用例集` 带出，**`判定` 列自动出「通过 / 不通过」**（等级命中 + 分数落区间 + 关键词命中，三重校验）；
- 底部自动统计通过率，无需人工比对。

### 3. 稳定性抽样

对 TC-07（阈值敏感用例）与 TC-09（封顶用例）各跑 3 次，记录极差，对比「≤ ±5 分」这条线。

## 五、测出来不对，怎么定位（四路归因）

新手通病：结果不对 → 直接改提示词 → 还是不对 → 再改 → 越改越乱。正确顺序是往上游找：

| 症状 | 先查哪里 | 大概率原因 | 动作 |
|---|---|---|---|
| 属性分 / 行为分不对 | **查代码，别查模型** | 前端选项文案与 `rules` 字典键不一致，切词后匹配失败计 0 | 逐字对齐选项与字典键（5 秒解决，改提示词一辈子也解决不了） |
| 意图分忽高忽低 | 先看提取对不对 | 提示词档位边界模糊 / 温度太高 | 温度降到 0.2；每档补一个 few-shot 例句 |
| 走了兜底 8 分 | 看模型原始输出 | 没按 JSON 格式返回 | 提示词贴标准 JSON 示例；加 `is_fallback` 标记做观测 |
| 话术答非所问 / 编造 | 查检索结果 | 知识库分段太碎 / 未覆盖该话题 | 开 rerank；强化「资料未覆盖的写需与产品确认」 |

**调 AI 像医生调药：一次只动一味药。** 同时改三样、结果变好了，你不知道是哪一味起效，下次出问题还是抓瞎。
